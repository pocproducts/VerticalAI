```
Frontend (Next.js)                    Backend
┌─────────────────┐                 ┌─────────────────┐
│ api-client.ts    │                 │ FastAPI          │
│ const API_URL =  │  proxy rewrite  │ (Fiscal-Agent)   │
│ "/api" (default) │  ────────────►  │                 │
│                  │  /api/v1/health │ /v1/health       │
│                  │  ────────────►  │                 │
│ .env.local:      │  /api/v1/system│ /v1/system       │
│ http://localhost:8000 │  /metrics  │ /metrics         │
└─────────────────┘                 └─────────────────┘
```

- **Proxy**: Next.js rewrite: `/api/:path*` → `http://localhost:8000/:path*`
- **API Base URL**: `NEXT_PUBLIC_API_URL=http://localhost:8000` (`.env.local`)
- **Auth**: Bearer token opcional via `NEXT_PUBLIC_API_KEY` → header `Authorization: Bearer {key}`
- **Timeout**: 15 segundos
- **Content-Type**: Siempre `application/json`
- **Estrategia de fetch**: 5 endpoints en paralelo con `Promise.allSettled`

## 8. Notas Técnicas para el Backend

### Routing

El frontend llama a `/api/v1/health` que Next.js proxy a `http://localhost:8000/v1/health`. El backend sirve en `/v1/...`.

### Tolerancia a Fallos

El frontend está diseñado para fallar gracefulmente:
- Si un endpoint falla → muestra "Servicio no disponible" en esa sección
- Si `latencyData` es null → muestra "Servicio no disponible"
- El resto de las secciones con mock data (Incidents, Deployments, etc.) no dependen de ningún endpoint
- Esto permite **rollout incremental**: implementar endpoint por endpoint

### Priorización Interna

Para el caso de Fiscal-Agent, los endpoints más naturales de implementar primero serían:

1. **Health** — ya hay health checks, solo hay que exponerlos como endpoint con latencias
2. **Services** — los componentes del sistema (CLI, API, MCP, Browser) pueden mapearse como servicios
3. **Metrics** — el pipeline ya genera runs con éxito/error, solo hay que time-series
4. **Activity** — el MemoryClient ya guarda eventos, hay que unificarlos
5. **Errors** — los errores del pipeline pueden estructurarse como top_errors + trend

El resto (Incidents, Deployments, Performance, SLA, On-Call, Postmortems) requiren features que Fiscal-Agent hoy no tiene.
